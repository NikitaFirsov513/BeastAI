# BeastAI: требования к первой версии

Состояние: стартовые функциональные требования зафиксированы, этап 1 плана. Аппаратные бюджеты уточняются после проверки совместимости. Обновлено 1 ноября 2026 года.


Текущий фокус по просьбе пользователя: данные и обнаружение животных; исследование координат/геопривязки отложено до соответствующего этапа. Все скачиваемые данные и результаты сохранять в D:\PROJECTS\PYTHON\BeastAI.

Рабочий сценарий из плана: цветная дневная съёмка с воздуха; видимые олени/косули на открытых участках и опушках; один класс animal. Первая полная версия обрабатывает записанное видео на компьютере.

Принятые требования и рабочие ориентиры

Пользователь выбрал R1 = 90% и поручил остальные стартовые решения принимать по рекомендации. R2 принят из предложенной рекомендации; R3 и R4 ниже выбраны как первоначальные проектные цели. Их достижимость ещё не подтверждена измерениями и уточняется по данным, геометрии съёмки и целевой плате.

R1. Доля обнаруженных животных в проверочном видео — не менее 90%.

Смысл: из 100 целевых животных/наблюдений, представленных эталонной разметкой проверочного видео, система должна обнаружить не менее 90 хотя бы один раз за время их присутствия. Несколько соседних кадров одного размеченного животного не увеличивают число проверочных случаев.

Для реализации проверки понадобятся эталонные номера животных между кадрами. Единица проверки — размеченная траектория присутствия в выбранной видеопоследовательности; постоянная идентификация особи между разными полётами в это требование не входит. Точные правила сопоставления события и траектории, минимальная длительность видимости и подтверждение события будут описаны явно до итогового замера.

Для итогового R1 обнаружением считается подтверждённое событие, сопоставленное с эталонной траекторией, в журнале наблюдений. Одиночные рамки детектора оцениваются отдельно и не подменяют результат всей цепочки. Событие может пока не иметь координат, если геопривязка недоступна; качество координат проверяется отдельно по R4.

Это цель разработки для определённого проверочного набора и сценария, не гарантия для любых полётов. Размер выборки и неопределённость оценки указываются вместе с результатом. Малые животные оцениваются отдельно; отдельная минимальная доля для этой группы пока не согласована.

Текущее состояние проверки

- Результат 83/115 относится к рамкам на отдельных изображениях, а не к разным животным в видео. Из него нельзя вычислить выполнение R1.
- Нынешние 32 изображения остаются неизменной разработческой проверкой.
- Для итоговой оценки R1 нужна отдельная видеоразметка с разделением исходных данных по полётам; итоговый набор не используется для обучения и подбора настроек.

R2. Не более одной ложной подтверждённой тревоги за 10 минут обработанного видео.

Измерять число ошибочных новых событий на суммарную длительность согласованного проверочного видео: не более 0,1 события в минуту. Повторные рамки одного ошибочного трека считаются одним событием. Лишние новые события, в том числе повторный учёт уже сопоставленного животного, учитываются как ошибки при сопоставлении событий один к одному с эталоном. Правила временного объединения и подтверждения фиксировать до итоговой оценки. Частоту на пустом фоне также сообщать отдельно. Указывать длительность видео и неопределённость измерения; короткий клип без ошибок не доказывает выполнение требования в любых условиях.

R3. Первоначальные цели по времени реакции.

- Подтверждённое событие — не позднее 2 секунд после первого эталонного появления животного, как минимум для 95% успешно обнаруженных наблюдений. Пропущенные животные отдельно ухудшают R1; их нельзя скрывать за статистикой задержек только успешных событий.
- Полная обработка одного выбранного кадра — не более 200 мс как минимум в 95% измеренных вызовов, по одному входу сети за запуск. Включать получение/декодирование, подготовку, все вызовы детектора, рамки, трекер, расчёт координат и запись события по мере появления этих этапов. Время ожидания уже устаревшего кадра в очереди тоже учитывать при оценке реальной задержки; очередь не должна постоянно расти.
- Частота запуска детектора пока не назначена: выбирать её по видео с сохранением R1, R2 и задержки подтверждения. Бюджет 200 мс сам по себе не означает обязанность запускать детектор на каждом кадре камеры.
- Эти цифры — начальные требования для проектирования. Замеры RTX 4060 не подтверждают их выполнение на будущей плате.

R4. Первоначальная цель ошибки координат — не более 10 метров для 95% сопоставленных географических измерений.

Проверять сначала на имитации с известными ответами, затем отдельно на реальных неподвижных точках с известными координатами. Имитация не подтверждает реальную точность полёта. Для животных дополнительно понадобятся достоверные эталонные координаты или честное ограничение оцениваемых показателей. Не выдавать известную ошибку геопривязки контрольных точек за полную доказанную точность всех наблюдений животных. Учитывать синхронизацию кадров, положение и направление камеры, параметры объектива и рельеф. Цель 10 м уточняется после выбора геометрии съёмки и доступных данных.

R5. Аппаратные бюджеты — после проверки целевого исполнения.

Числа предельной RAM и мощности не назначены без устройства и профилирования. Выбирать самую экономичную измеренную реализацию, выполняющую требования качества и времени. Для каждого режима записывать память процесса и вычислителя, модель, разрешение, число последовательных запусков/размер пакета, числовую точность, полную задержку и условия измерения. На реальном устройстве измерять мощность и энергию кадра с указанием границ: ускоритель либо вся плата/цепочка. Около 1 TOPS — предварительный ориентир; плата не выбрана. До покупки проверить поддержку операций и компиляцию модели. Покупки и платные ресурсы обсуждаются отдельно.
