```powershell
.\.venv\Scripts\python.exe analyze_bambi.py
```

## Как получены снимки

`fetch_bambi.py` извлекает отдельные JPEG и RGB-разметку из архивов Zenodo HTTP-запросами диапазонов байт. Полные архивы и тепловизионные снимки не скачиваются. Если сервер игнорирует диапазон, программа прекращает чтение до загрузки тела. Исходные архивы и их размеры указаны в сохранённых метаданных; контрольные суммы файлов, CRC32 членов ZIP и объём переданных диапазонов записаны в индекс.

Сначала прочитаны оглавления и метаданные 12 небольших полётов, затем выбраны 7 с проверенной RGB-разметкой оленей. Для первого осмотра взяты кадры, в которых все строки RGB MOT соответствуют согласованной разметке видимых оленей. Это намеренно простая положительная выборка, не репрезентативная оценка будущей работы на всех кадрах. Скрытые животные и пустой фон ещё не представлены.

Обучающая и проверочная части разделены по ID полёта, а не по соседним кадрам. Пространственная независимость разных полётов ещё не проверена. Разметка покрывает проверенные траектории, но не обязательно каждое животное в кадре; предсказания без пары требуют визуальной проверки, прежде чем называть их ложными.

Источники: https://zenodo.org/records/21291168 и https://zenodo.org/records/21298044. В обычном наборе BAMBI исходные рамки тепловизионные: они не используются как RGB-разметка без совмещения. Здесь взят отдельный выпуск с проверенными RGB MOT-рамками.

# Просмотрщик WAID

Программа скачивает оригинальные цветные снимки и соответствующие текстовые файлы рамок, хранит их отдельно и накладывает разметку в браузере. Рамки взяты из датасета, нейросеть ещё не запускается. Требуется Python 3.10 или новее; дополнительные библиотеки не нужны.

## Первый запуск

Дважды нажмите `start_preview.cmd` в этой папке. Он загрузит 300 пар «снимок + разметка» и откроет локальный просмотрщик. Окно программы оставьте открытым. Остановить просмотрщик можно сочетанием Ctrl+C в этом окне.

В браузере доступны переключатели рамок и категорий, увеличение снимков, поиск по имени, фильтр по части набора и страницы по 12 снимков. На увеличенном снимке переключатели продолжают действовать; закрытие — Esc. Рамки не записываются в исходные фотографии.

## Файлы

```text
data/waid/
  index.json         — версия источника и полный список файлов
  images/
    train/           — исходные изображения
    valid/
    test/
  labels/
    train/           — отдельные текстовые файлы разметки
    valid/
    test/
```

Имена изображения и его разметки совпадают, расширения отличаются. Строка разметки: `категория центр_x центр_y ширина высота`. Последние четыре числа выражены долями размеров изображения. Категории пока сохранены как в оригинальном наборе; объединение в `animal` будет отдельным шагом подготовки к обучению.

## Полный набор

`download_all.cmd` скачивает **все пары** текущей зафиксированной версии WAID. Не запускайте его для первого знакомства, если достаточно 300 снимков. Точный размер и число файлов показывает команда `python waid.py inspect`. Архив и история Git не скачиваются. Повторная загрузка проверяет содержимое по контрольным суммам Git и пропускает исправные файлы; повреждённые скачивает заново. Незавершённые файлы имеют расширение `.part` и не появляются в просмотрщике.

После дополнительной загрузки перезапустите просмотрщик, чтобы он увидел новые снимки.

## Команды для PowerShell

Рабочая папка проекта: `D:\PROJECTS\PYTHON\BeastAI`. Откройте PowerShell и выполните `cd D:\PROJECTS\PYTHON\BeastAI`. Затем выполняйте команды по отдельности:

```powershell
python waid.py inspect
```

Первая команда получает только список файлов и показывает размер полного набора. Вторая скачивает небольшую повторяемую выборку из трёх исходных частей. Третья запускает просмотрщик на `http://127.0.0.1:8765/`, доступный только на этом компьютере. Другой порт: `python waid.py serve --port 8766 --open`.

## Границы текущего шага

Выборка из 30 снимков предназначена для осмотра, а не для оценки качества. Сохраняется исходное разделение train/valid/test; его независимость по полётам ещё не проверена. Категории и исходная разметка не меняются. Пустой файл, отсутствующая разметка и неверные строки различаются в интерфейсе. Неверные строки не рисуются; показывается сообщение об ошибке.

При первом запуске нужен доступ к `api.github.com` и `raw.githubusercontent.com`. При сетевом сбое можно повторить запуск: завершённые загрузки сохраняются. После скачивания просмотрщик работает без интернета.

Источник: https://github.com/xiaohuicui/WAID. Программа фиксирует версию репозитория в `index.json` и получает все файлы из этой версии.

## Первый запуск нейросети (без дообучения)

Для этого опыта выбрана готовая YOLO11n, обученная на COCO. Нужны PyTorch с CUDA и Ultralytics; в окружении проекта версии зафиксированы в `requirements-inference.txt`. Модель и её кэши сохраняются внутри `data/`. Просмотрщик сам по себе по-прежнему использует только стандартную библиотеку Python.

`run_baseline.cmd` запускает готовую модель на уже скачанных снимках из train и valid. Это использование модели: веса не меняются. Часть test не обрабатывается. После завершения обновите страницу просмотрщика: зелёный слой показывает разметку авторов, синий пунктирный слой — предсказания. У снимка без запуска показывается отдельное сообщение; ноль предсказаний не означает отсутствие запуска.

Команда PowerShell из папки `D:\PROJECTS\PYTHON\BeastAI`:

```powershell
.\.venv\Scripts\python.exe baseline.py
```

Результаты: `data/baseline/latest.json` и отдельный отчёт с временем запуска в имени. Они содержат версию данных, контрольную сумму модели и снимков, версии программ, оборудование, размер входа, числовую точность, пороги, расход памяти и задержки. Размер входа по умолчанию 640 × 640, по одному кадру за запуск, FP32 (32-битные числа). Пропорции изображения сохраняются, свободное пространство дополняется полями.

Перед измерениями отдельно выполняются первый запуск и пять прогревочных кадров. Для каждого изображения затем три раза измеряется вся цепочка: чтение/декодирование, подготовка, нейросеть, подавление повторных рамок, передача результатов в память процессора и преобразование координат. Загрузка модели, разметки, запись отчёта и рисование в браузере не входят в эту задержку. Чтение может использовать файловый кэш Windows. Записываются медиана и 95-й процентиль: граница, ниже которой оказались примерно 95% замеров. Энергия кадра пока не измеряется. Максимальная память PyTorch на GPU не включает драйвер и другие процессы.

Предварительное сравнение качества делается только на маленькой уже скачанной части valid. Все категории разметки считаются одним animal; принимаются предсказания категорий животных COCO. Совпадение рамок считается при IoU не меньше 0,5 (площадь пересечения рамок, делённая на площадь их объединения), каждому животному соответствует не более одного предсказания. Дополнительно записываются пропуски животных с площадью рамки меньше 32 × 32 пикселей после уменьшения входа. Это рабочее определение малого объекта для данного отчёта, а не стандартная итоговая метрика COCO.

Готовая модель COCO не содержит всех категорий WAID, в частности seal и camelus. Слабое исходное качество ожидаемо и само по себе не доказывает непригодность выбранной архитектуры. Маленькая выборка и ещё не проверенное разделение по полётам не позволяют считать отчёт надёжной оценкой будущего проекта. Перед подбором настроек будет закреплена более подходящая независимая проверочная выборка.

Источники: https://docs.ultralytics.com/models/yolo11/ и https://pytorch.org/get-started/previous-versions/.

## Расширение до 300 снимков

После первого опыта выборка расширена с 30 до 300 пар (по 100 из train/valid/test). Первые 30 входят в неё без изменений. Полный размер этой выборки — около 31,7 МиБ. Файл start_preview.cmd теперь поддерживает эту выборку и пропускает исправные уже скачанные файлы.

Загрузка дополнительных снимков не меняет веса модели. На новых train/valid запускается та же готовая YOLO11n с прежними настройками.
